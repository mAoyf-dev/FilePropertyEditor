# 作者信息与新版检测下载设计

## 目标
以仓库所有者 mAoyf-dev 为本项目作者，显示主页 https://github.com/mAoyf-dev 和仓库 https://github.com/mAoyf-dev/FilePropertyEditor。保留 REA 报告对原版作者的历史归属。

## 方案
方案 1：新增“关于”和“检查更新”，后台查询 GitHub 最新正式 Release，比较数字版本。发现新版后显示版本与说明，用户点击下载时在默认浏览器中打开该 Release 的发行附件链接，由浏览器保存文件。匹配当前 x86/x64 附件，双架构压缩包也可用；无对应附件时打开发布页。无需安装服务、不自动运行下载内容，保持单文件绿色版。
已选方案 2：在程序内下载，提供保存位置、进度和取消，先写临时文件，成功后再保存为目标文件；需要额外的下载状态和失败清理逻辑。

## 范围
关于界面、作者主页/仓库链接、EXE 版本资源、README；更新查询、版本解析和附件匹配；双架构构建及错误路径测试。计划将新增功能版本定为 2.1.0。统一版本定义以防比较与资源版本不一致。

## 行为约束
只主动点击时联网；无 Release 与已是最新版分别提示；连接超时、GitHub 限流、无网络不能阻塞主界面；使用 HTTPS 和系统证书验证；仅允许指向本仓库的发布与附件链接。版本响应设大小上限并严格解析，不采信说明文本中的命令。不同架构不能误选。

## 验证
测试版本新旧比较、无效版本、JSON 转义与缺失字段、附件架构选择和不可信 URL；编译测试 x86/x64。实网检查发布状态；没有新版时不声称完成新版实物下载测试。

## 发布边界
此修改不自动提交、推送或创建 GitHub Release。发行方后续需要发布正式版本并上传附件，用户端才能发现和下载该版本。
